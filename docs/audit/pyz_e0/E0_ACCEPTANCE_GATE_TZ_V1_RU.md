# Master Cancer Landscape — ТЗ Э0-ACCEPTANCE v1.0

**Дата:** 16 ноября 2026 г.  
**Статус:** черновой этап инженерной подготовки формальной приёмки; это не акт утверждения.  
**Основание:** базовое Э0 ТЗ и `docs/audit/pyz_e0/README.md`, `docs/audit/pyz_e0/CLOSEOUT_RU.md` в PR №5; последовательность черновых PR №5–9.

## 1. Цель

Собрать в одном проверяемом отчёте доказательства и незакрытые вопросы по критериям AC-01…AC-09, установить фактическую готовность MCL/PYZ к формальной научной приёмке и подготовить безопасное решение о порядке дальнейшей интеграции. Избежать преждевременного объявления результата E0 принятым на основании одного кода возврата 0, девяти скриншотов, найденного DOI или успешного CI.

## 2. Граница этапа

- **Вход:** уже существующие `MCL_PYZ_E0_CLOSEOUT.zip`, папка исходного Э0-отчёта либо аналогичная архивная копия с `E0_ACCEPTANCE.md`; при наличии — текущая папка научных файлов для повторной SHA-проверки.
- **Выход:** `gate_report.json`, `acceptance_matrix.tsv`, `findings.tsv`, `source_hash_reconciliation.tsv`, `E0_ACCEPTANCE_GATE_RU.md` и единый ZIP внутри `MCL_Project/reports`.
- **Источник истины:** научные Parquet/TSV и исходный контрольный отчёт Э0; исходное содержимое не изменять. Новые файлы — только в новом каталоге отчёта.
- **Не входит:** повторная загрузка BindingDB/ChEMBL, изменение сайта/API, перерасчёт DepMap/PRISM, вмешательство в PS1/PS2, ADMET-анализ и автоматический merge/rebase/reset/clean.
- **Особое правило по ADMET:** существующие поля разрешено проверять только на корректную передачу источник→API; они не участвуют в приоритизации или выводах о безопасности. Внешний ADMET-модуль будет интегрирован отдельно.

## 3. Обязательные проверки

| ID | Что проверяем автоматически | Что обязательно делает эксперт |
|---|---|---|
| AC-01 | Наличие версий, исходных SHA-256 и сверки с первым этапом закрытия | Подтверждает научный набор данных и базовый коммит |
| AC-02 | Инвентарь источников, незавершённые строки и блокеры схемы | Рассматривает исходники с `NOT_REVIEWED`, версии и происхождение |
| AC-03 | Пары PYZ×мишень (65×13), уникальность и допустимые состояния | Проверяет, что покрытие не приравнивается к измеренной активности |
| AC-04 | Наличие и статусы сопоставления исходный файл→API | Проверяет контрольные карточки PYZ-001/035/051/055/065 и экран |
| AC-05 | Наличие девяти PNG, их сигнатуры и протокол браузера | Проверяет читаемость, адаптивность, управление, ошибки |
| AC-06 | Наличие результатов производительности и холодного старта | Принимает эксплуатационные требования и ограничения кэша |
| AC-07 | Наличие ссылок на исследуемые референсы | Проверяет методики, строение и достоверность, разграничивает референсы и PYZ |
| AC-08 | Сверка SHA до/после, по возможности новый расчёт SHA текущих исходников | Разбирает любой конфликт/отсутствующий файл |
| AC-09 | Фиксация статуса пакета доказательств | Подписывает научную приёмку или отказ, утверждает дальнейшие действия |

Автоматическая проверка может выставлять `AUTO_EVIDENCE`, `PENDING_MANUAL`, `MISSING_EVIDENCE`, `BLOCKED`. Отдельное ручное решение всегда `PENDING`, пока оно не оформлено владельцем проекта; даже `AUTO_EVIDENCE` не означает `APPROVED`.

## 4. Методология и защита от ложных выводов

1. Программа строго проверяет состав входных файлов, структуру TSV/JSON, SHA-256, происхождение путей и отсутствие дублирующихся имён в ZIP. Архив не распаковывается.
2. Проверяется полное совпадение записанных SHA-256 каждой исходной научной позиции между базовым отчётом, входом и выходом closeout; при наличии `--science-root` отдельно хешируются текущие файлы исходников. Показатель `fresh_live_sha_checked` не может быть истинным без такого повторного хеширования.
3. Неизвестные/пустые данные, нарушенные связи, неполный архив или ошибочный экспериментальный статус **не** замещаются догадками или успешным статусом других PR.
4. При расхождении исходников/API или ошибочном/дублированном покрытии результат `BLOCKED`; при недостатке данных — `INCOMPLETE_EVIDENCE`; при закрытых машинных проверках — максимум `PENDING_OWNER_ACCEPTANCE`.
5. Никакое значение Ki/Kd/IC50 известного лиганда не переносится на PYZ. Данные Э1-P0-B3A могут быть дополнительной научной справкой, но не способны автоматически закрыть AC-07.
6. Значения `merge_permitted=false` и `scientific_status=NOT_ACCEPTED_MANUAL_REVIEW_REQUIRED` остаются неизменными для автоматического инструмента.
7. Отчёт имеет отдельный новый каталог; при существовании папки выходной результат не перезаписывается.

## 5. Размещение и сценарий

Вся работа выполняется в едином `MCL_Project`:

- Код: `MCL_Project/repositories/master-cancer-landscape` и отдельное аудиторское worktree `MCL_Project/repositories/mcl-pyz-e0-acceptance-review`.
- Входной отчёт: поиск внутри `MCL_Project/reports` или в оставшемся старом архиве `Desktop/MCL_PYZ_E0_CLOSEOUT.zip`. Не создаём новый проект и не копируем гигабайтную BindingDB.
- Выход: новая папка `MCL_Project/reports/E0_ACCEPTANCE_GATE_<timestamp>` плюс `MCL_E0_ACCEPTANCE_GATE_<timestamp>.zip`.
- Запуск: `scripts/run-pyz-e0-acceptance-gate.ps1` (PowerShell 5.1/7, Python 3.13 из основной `.venv`; без установки новых библиотек).

## 6. Условия приёмки технической реализации

- Отдельная черновая ветка и PR на основе PR №5, без изменения его содержимого или других PR.
- Автотесты проверяют архив и папку отчёта, отсутствующий closeout, неверный SHA, неполное покрытие, несоответствие API, повреждённый PNG, некорректные ZIP-пути, дубликаты, запрет перезаписи и неизменность исходника.
- Документация описывает, что *код 0 = отчёт создан*, но не *Э0 принят*.
- Фактическая приёмка Э0 останется открытой, пока исходный реальный отчёт не получен и критерии не подтверждены пользователем.

## 7. Интеграция после ручного решения

PR №5 (Э0) должен быть рассмотрен на собственной базе `feature/pyz-card-v2-p0`. PR №6 (индивидуальные наблюдения), №7 (референсные лиганды), №8 (экспериментальные доказательства) и №9 (литературная проверка) остаются черновыми до проверки зависимостей и отдельных результатов. Автоматического объединения не делать.

**Итоговый продукт этапа:** не новая оценка активности PYZ, а проверяемый реестр готовности MCL и список оставшихся работ по безопасности научных выводов.

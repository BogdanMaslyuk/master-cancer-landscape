# MCL / Э0-AC-05 — ТЗ v1.0: полноценная проверка интерфейса в браузере

**Статус:** реализация аудита, не приёмка Э0. **Основание:** консолидированный реальный отчёт `MCL_E0_ACCEPTANCE_GATE_20261116_174657_995.zip`: 9 PNG, сделанных через Edge/Chrome CLI с методом `viewport-only`, без проверки DOM, JavaScript и клавиатуры. Статус всех старых `CAPTURED`, а не `AUTO_PASS`.

## Цель

Подтвердить/опровергнуть видимые на прежних мобильных снимках признаки обрезания страницы MCL и научиться объективно отличать корневую горизонтальную прокрутку от разрешённой прокрутки таблиц. Установить, что `/pyz`, `/pyz/PYZ-035`, `/pyz/matrix` правильно открываются и обеспечивают доступ клавиатурой. Не менять CSS без новых объективных данных.

## Объём

- Три страницы × три размера окна (1440×900, 768×1024, 390×844) = **9 браузерных сценариев**.
- Использовать **настоящий Playwright Chromium с установленным Edge/Chrome**, а не `--headless --screenshot` из командной строки без браузерных измерений.
- Сохранить по каждому сценарию HTTP-код, `h1`/ожидаемый заголовок, ошибки JavaScript/HTTP 5xx, `window.innerWidth`, `documentElement.clientWidth/scrollWidth`, `body.scrollWidth`, `visualViewport.width`, оценку глобального переполнения, внешние элементы, прошедший фокус Tab, время до DOMContentLoaded, PNG и SHA-256.
- Внутренняя горизонтальная прокрутка **таблицы** не равна переполнению всей страницы. Никаких фиктивных `HTTP_NOT_200` или `KEYBOARD_FOCUS_MISSING`, когда измерение не выполнялось.
- Дополнительно, если существует исходный `ui_expected.json` Э0, сравнить DOM-заголовки и SMILES контрольных PYZ с исходно сохранёнными значениями. Это проверка передачи данных, не исследование активности.

## Пределы и безопасная архитектура

- Один корень: `%USERPROFILE%\MCL_Project`. Только чтение API `127.0.0.1:8100`, сайта `127.0.0.1:3100`, научного реестра. Запускающий скрипт проверяет, что `/health.mcl_root` равен центральной научной папке.
- Не создавать сайт/API, не выключать чужие процессы, не изменять исходные Parquet/TSV/.npy, Git ветки пользователя или кэш Next.js.
- `playwright-core` устанавливается **только при отсутствии** в `MCL_Project/reports/_tools/ac05` без скачивания браузера (используется системный Edge/Chrome).
- Отчёты: только `MCL_Project/reports/AC05_BROWSER_<timestamp>/` плюс `MCL_E0_AC05_BROWSER_<timestamp>.zip`. Создание нового результата — без перезаписи ранее созданных.
- Не выполнять ADMET-расчёты; существующие базовые дескрипторы имеют исключительно справочный характер.
- На всех стадиях `scientific_acceptance=NOT_ACCEPTED`, `merge_permitted=false`, даже если все 9 браузерных сценариев пройдут.

## Критерии завершения автоматической части

- Записаны все девять исходов, в том числе явные ошибки/пропуски; отсутствующие проверки не выдаются за удачные.
- Для каждой страницы сохраняется снимок + хэш, фактическая метрика глобальной ширины и диагностические списки потенциально выходящих за границы элементов.
- Результаты доступны в `browser_results.json`, `ui_diagnostics.tsv`, `source_dom_comparisons.tsv`, `AC05_REVIEW_RU.md`, `screenshots/*.png` и итоговом ZIP.
- JS синтаксис проходит `node --check`; чистые проверки логики проходят в Node tests; проверки Python/фронтенда проходят в GitHub CI.
- Ручная визуальная оценка снимков и подтверждение найденных CSS-дефектов остаётся обязательной до принятия AC-05.

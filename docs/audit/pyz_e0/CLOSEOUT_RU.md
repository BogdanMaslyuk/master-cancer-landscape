# MCL/PYZ — Э0: закрывающая автоматизированная проверка

**Основание:** мастер-ТЗ PYZ v1.0; отдельное ТЗ Э0 v1.0; исходный запуск `MCL_PYZ_E0_REPORT.zip` (`20261114T085303Z-bc5a835b`). Эта инструкция дополняет исходный `docs/audit/pyz_e0/README.md`, **не меняет научную модель и не подтверждает Э0 автоматически**.

## Назначение

Сохранить дополнительные проверяемые сведения для критериев AC-01…AC-09:

1. **AC-01/08:** независимая повторная проверка SHA-256 каждого пути из `file_checksums.sha256` исходного E0, до и после закрывающего запуска. Не считать изменение файла дефектом аудитора без расследования причин.
2. **AC-04/07:** сравнение зарегистрированных SMILES, индивидуальных QED/ADMET и четырёх полей всех мишеней для PYZ-001, -035, -051, -065, плюс PYZ-055. Сопоставление идёт **исходная TSV/Parquet → API**, не выдаёт равенство за доказательство активности.
3. **SCI-01/02:** сохраняются реальные записи `PYZ-035 → CDK4`, `PYZ-055 → BCL2L1` с ID известных аналогов, типом агрегированного endpoint, знаком отношения (если есть) и источниками, а также независимые записи разных известных препаратов на клеточных моделях. **`assay_id` в текущем источнике отсутствует** и не выдумывается. Для проверки публикации нужен отдельный первичный набор/исходный экспериментальный протокол.
4. **AC-05:** 9 исходных PNG сайта (`/pyz`, `/pyz/PYZ-035`, `/pyz/matrix`, каждый при 1440×900, 768×1024, 390×844), техническая проверка HTTP/заголовка, внешней горизонтальной прокрутки, JS-ошибок и возможности перехода клавишей Tab. Дополнительно сверяются **SMILES четырёх контрольных PYZ** с текстом страницы. Это автоматическая проверка, **не WCAG-аудит и не визуальное экспертное утверждение**.
5. **AC-06:** отдельный запуск свежего процесса FastAPI на временно свободном порту 127.0.0.1 с `--no-reload`, замер времени готовности и первого ответа PYZ-035. Чужие процессы, порты 8100/3100 и файлы научных данных не меняются. Имеющиеся тёплые замеры исходного E0 сохраняются.
6. **Кэш:** фиксируются заголовки API и конфигурация Next.js (`force-cache`, типовой срок 300 секунд). **Поведение после изменения источника не подтверждается** без безопасного отдельного тестового набора; запрещено менять рабочие Parquet ради проверки.

## Требования к окружению

- Windows 10/11, PowerShell 5.1 или PowerShell 7; Python из рабочего окружения MCL (pandas, pyarrow, FastAPI/uvicorn). Исходные файлы MCL должны оставаться в `mcl-pyz-v2-review`.
- PS1 запущен на `http://127.0.0.1:8100` и читает **ту же папку**, PS2 — на `http://127.0.0.1:3100`.
- Node/npm и установленный **Microsoft Edge или Google Chrome** нужны для автоматических скриншотов. `playwright-core` устанавливается только в исключённую из Git папку `mcl-pyz-e0-audit/outputs/audits/pyz_e0/_ui_tools`; браузер не скачивается и не заменяется.
- При невозможности установить пакет/запустить браузер остальная проверка продолжается, AC-05 остаётся `NOT_REVIEWED`.

## Запуск

Откройте PS0 и включите PS1/PS2 (оба должны относиться к `mcl-pyz-v2-review`). **Не создавайте рабочее дерево заново**: ранее было создано отдельное `mcl-pyz-e0-audit`.

```powershell
$ErrorActionPreference = "Stop"
$Audit = "$env:USERPROFILE\Desktop\mcl-pyz-e0-audit"
$Review = "$env:USERPROFILE\Desktop\mcl-pyz-v2-review"
git -C $Audit fetch origin feature/pyz-e0-baseline-audit
if ($LASTEXITCODE -ne 0) { throw "Не удалось загрузить ветку Э0" }
git -C $Audit merge --ff-only origin/feature/pyz-e0-baseline-audit
if ($LASTEXITCODE -ne 0) { throw "Ветка Э0 не обновлена" }
& "$env:SystemRoot\System32\WindowsPowerShell\v1.0\powershell.exe" -NoProfile -ExecutionPolicy Bypass `
  -File "$Audit\scripts\run-pyz-e0-closeout.ps1" -MclRoot $Review
```

Флаг `-SkipBrowser` пропускает установку Playwright/снимки, `-SkipColdApi` — отдельный процесс API. Оба пропуска отмечаются в отчёте, а не считаются успехом. Флаг `-NoZip` запрещает создание ZIP.

## Где результат

Исходный `outputs/audits/pyz_e0/<run_id>/` не перезаписывается. В **подпапку `closeout/`** записываются:

| Файл | Что подтверждает / ограничение |
|---|---|
| `source_sha_entry.tsv`, `source_sha_after.tsv` | Входные и повторные SHA-256; при несовпадении — блокер |
| `source_api_reconciliation.tsv` | Значения исходных структур, ADMET и мишеней vs live API; **не научный assay-аудит** |
| `scientific_reference_examples.tsv` | Известные лиганды двух пар, их агрегаты, отсутствующие primary assay IDs |
| `cell_context_observations.tsv` | Несколько разных известных препаратов/ролей в одной модели; не PYZ-эффекты |
| `cold_api.json`, `cold_api_server.log` | Собственный отдельный старт API, первый ответ, ошибки |
| `cache_diagnostics.json` | Действующие заголовки и настройки кэширования; нет теста обновления Parquet |
| `ui/ui_checklist_automated.tsv`, `ui/screenshots/*.png` | 9 скриншотов и технические браузерные проверки |
| `ui/browser_results.json`, `ui_expected.json` | Результаты загрузки и сверки SMILES в DOM |
| `E0_ACCEPTANCE_CLOSEOUT.md`, `E1_HANDOFF_CLOSEOUT.md` | Консервативный вердикт по AC и задачи Э1 |

Скрипт собирает весь исходный отчёт **вместе** с `closeout/` в `Desktop/MCL_PYZ_E0_CLOSEOUT.zip` для последующей проверки.

## Что останется ручным

- Оценить девять реальных скриншотов: читаемость, раскрытие разделов, текст предупреждений, корректность мобильного режима, переходы и скроллинг.
- По первоисточникам оценить хотя бы одну экспериментальную запись известного лиганда для PYZ-035/CDK4 и PYZ-055/BCL2L1: конкретный `assay_id`, метод, условия, знак `<`/`>`, химический идентификатор, публикация, единство конечной точки.
- Проанализировать семь источников `NOT_REVIEWED` из входного E0 или оформить их как документированное ограничение, если они не нужны в карточке.
- Решить, нужен ли отдельный контролируемый тест изменения кэша на **копии** данных. Рабочие файлы изменять нельзя.
- Принять/отклонить AC-09. **Скрипт никогда не утверждает Э0 от имени научного руководителя/владельца проекта.**

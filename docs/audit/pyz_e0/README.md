# PYZ Э0 — базовая приёмка и инвентаризация

Основание: отдельное ТЗ «MCL — Э0. Базовая приёмка и инвентаризация MCL/PYZ», редакция 1.0 от 14 ноября 2026 г.; мастер-ТЗ PYZ v1.0.

## Граница этапа

**Аудитор только читает исходные данные.** Все новые файлы создаются в `outputs/audits/pyz_e0/<UTC>-<short SHA>/` **отдельного рабочего дерева с кодом аудитора**, где отчёты игнорируются Git. Аудируемое дерево не получает ни одного нового файла. Нет миграций, исправления научной модели, нового интерфейса, автоматических скачиваний или переобработки BindingDB/DepMap. Сценарии с аварийным выключением сервера и визуальные скриншоты остаются ручными и помечаются как `NOT_REVIEWED` до их проверки.

Исходная PYZ 2.0 остаётся в `mcl-pyz-v2-review`. Код аудитора можно разместить в **другом worktree** `mcl-pyz-e0-audit`, не копируя научные файлы.

## Как запустить в Windows PowerShell

В окне PS0 нажмите `1`, чтобы запустить PS1 API (8100) и PS2 фронтенд (3100) из исходного рабочего дерева. Откройте третий PowerShell, затем:

```powershell
$Review = "$env:USERPROFILE\Desktop\mcl-pyz-v2-review"
$Audit = "$env:USERPROFILE\Desktop\mcl-pyz-e0-audit"
git -C $Review fetch origin feature/pyz-e0-baseline-audit
git -C $Review worktree add --detach $Audit origin/feature/pyz-e0-baseline-audit
& "$Audit\scripts\run-pyz-e0.ps1" -MclRoot $Review
```

Если API/сайт пока не работают, можно получить **только файловый этап Э0-Б/В** без поддельных результатов API:

```powershell
& "$Audit\scripts\run-pyz-e0.ps1" -MclRoot $Review -Offline
```

Результаты находятся в `mcl-pyz-e0-audit/outputs/audits/pyz_e0/`. Научные файлы в `mcl-pyz-v2-review` не меняются и отчёты туда не записываются.

`--offline` оставляет `api_cases.tsv` и `performance.tsv` пустыми; акт Э0 остаётся неутверждённым. Код `2` означает зафиксированные **блокеры**, а не сбой записи отчёта. Код `0` означает лишь создание материалов, **не научную приёмку**.

В повторной проверке `git worktree add` запускать не нужно. Достаточно:

```powershell
& "$Audit\scripts\run-pyz-e0.ps1" -MclRoot $Review
```

## Что выдаёт Э0

- `environment.json`, `git_baseline.txt` — SHA, версии, местоположение и состояние рабочего дерева;
- `input_inventory.tsv`, `file_checksums.sha256`, `schema_audit.json`, `data_qc.md` — список источников, SHA-256, схемы/ошибки;
- `coverage_matrix.tsv` — фактические статусы `present/missing/duplicate/invalid` для PYZ × мишень;
- `api_cases.tsv`, `api_samples/*.json` — безопасные образцы и результат запросов, включая все 65 PYZ и PYZ-999;
- `performance.tsv`, `performance_method.md` — 3 прогрева и 20 тёплых замеров для каждого маршрута, медиана и p95;
- `reconciliation.tsv` — сверка источника и API; UI остаётся `NOT_REVIEWED`, пока не проверен вручную;
- `ui_checklist.tsv`, `screenshots/`, `defects.md`, `E0_ACCEPTANCE.md`, `E1_INPUTS.md` — ручной контроль и входы для Э1;
- `gene_index_verify.log` — фактический запуск текущего валидатора генов.

## Обязательная ручная приёмка

1. Проверить источники ↔ API ↔ экран для PYZ-001, PYZ-035, PYZ-051, PYZ-065; не передавать активность известных лигандов в PYZ.
2. Проверить 9 скриншотов `/pyz`, `/pyz/PYZ-035`, `/pyz/matrix` при 1440×900, 768×1024, 390×844; дополнительно ошибки, длинный SMILES и управление клавиатурой.
3. Зафиксировать холодный запуск отдельно от тёплых измерений. Проверить кэш Next.js (обычно 300 секунд), не меняя реальные исходники.
4. Проверить N-01…N-10 на синтетических фикстурах или в изолированной среде; сценарий отключения PS1 исполнять только с пользовательского согласия.
5. Утвердить `AC-01…AC-09`, подписать вердикт и устранить блокеры перед стартом Э1.

Нельзя считать обнаруженное в коде потенциальное ограничение автоматически доказанной ошибкой на локальном наборе данных.

# MCL — TLS V3 / P0.8. Локальная проверка экспериментальных источников

**Контракт:** `mcl-tls-v3-p08-local-source-validation-v2`
**Научная приёмка:** `NOT_APPROVED`; **слияние изменений:** запрещено.  
**Режим:** только чтение научных исходников, **без сети**.

## Зачем этот этап

TLS V3/P0.7 повторил 12 запросов ChEMBL: 0 завершились успешно (8 тайм-аутов и 4 HTTP 500). Повторять те же запросы без изменения способа доступа нецелесообразно. Необходимо проверить *полные локальные выгрузки* экспериментальных источников на первых шести белковых мишенях, где в P0.6 были предварительно пригодные измерения.

Тестовая панель не является новой лечебной или целевой панелью для PYZ и не даёт оценки доли «мишеней с лигандами» в протеоме.

Идентификаторы и HGNC взяты из конкретного реального архива P0.6 19.11.2026, не конструировались заново.

## Требования к файлам и происхождению

- **ChEMBL:** официальная выгрузка **SQLite** конкретного релиза (например `chembl_36_sqlite/...db`), уже распакованная локально. Программа не загружает её и не изменяет, подключается через SQLite URI `mode=ro` и `PRAGMA query_only=ON`. Проверяет наличие и обязательные столбцы `target_dictionary`, `target_components`, `component_sequences`, `assays`, `activities`, `molecule_dictionary`, `compound_structures`.
- **BindingDB:** официальный **`BindingDB_All_<YYYYMM>_tsv.zip`** или распакованный TSV, а не таблица с отдельными статьями или ответ API. Для большого ZIP TSV читается потоком, без распаковки на диск. Обязательны повторяющиеся столбцы `UniProt (SwissProt) Primary ID of Target Chain`; **нельзя заменять их текстовым `Target Name`**. Наличие нескольких цепей и другой видовой принадлежности отслеживается отдельно.
- Версии задаются явными метками `--chembl-release chembl_NN`, `--bindingdb-release YYYYMM`, а файлы закрепляются через SHA256, размер и путь. **В данной версии метка релиза задаётся оператором, а не независимо извлекается из выпуска**: сверяйте её с именем официального архива и данными издателя. Если версия не указана, обработка источника запрещена.
- В качестве базы происхождения используются P0/P0.6/P0.7 ZIP от 19.11.2026. Проверяются их контракты и перекрёстные контрольные суммы. Научные файлы и матрица 65×13 не затрагиваются.

Источники: [официальные загрузки ChEMBL](https://chembl.gitbook.io/chembl-interface-documentation/downloads), [официальные загрузки BindingDB](https://www.bindingdb.org/rwd/bind/chemsearch/marvin/Download.jsp), [схема ChEMBL и примеры SQL](https://chembl.gitbook.io/chembl-interface-documentation/frequently-asked-questions/schema-questions-and-sql-examples).

## Критерии доказательств

### ChEMBL

Для точного сопоставления необходимо одновременно:

1. Только human `SINGLE PROTEIN`, **один** компонент target и точный accession белка в `component_sequences`;
2. Данные `assays.assay_type=B`, `confidence_score=9`;
3. Измерение `activities.standard_type IN (Ki,Kd,IC50)`, единицы `nM`, число больше нуля, структура в `compound_structures`;
4. Точное `standard_relation = '='` отдельно от `<`, `>`, `<=`, `>=`;
5. Записи с `potential_duplicate` или `data_validity_comment` помечаются для рассмотрения, не приравниваются к качественным;
6. Сохранены идентификаторы target/assay/activity/molecule/document и DOI, если имеются.

Даже запись `ASSAY_METADATA_MATCHED_PRIMARY_REVIEW_REQUIRED` **не означает независимой проверки первичной публикации**. При превышении лимита `max_rows_per_target` сохраняется пометка `truncated`, а не притворное «полное покрытие».

### BindingDB

- Сопоставление выполняется **только по UniProt (SwissProt) Primary ID of Target Chain** среди всех повторяющихся колонок.
- **Одна цепь** с точным accession и согласованным видом даёт предварительное `SWISSPROT_PRIMARY_SINGLE_CHAIN_MATCH_ASSAY_REVIEW`. Несколько цепей/видовые конфликты — отдельный обзор, **не** чистая single-protein evidence.
- Для каждой строки сохраняются `Reactant_set_id`, `MonomerID`, SMILES, InChIKey, PMID, DOI, указание источника, отношение и число по Ki, Kd, IC50.
- Ширина каждой физической строки сравнивается с заголовком. Строки ожидаемой ширины, короткие строки, дополненные пустыми хвостовыми полями с обязательным статусом `SHORT_ROW_PADDED_REVIEW_REQUIRED`, и длинные отклонённые строки учитываются раздельно. Дополнение короткой строки без регистрации в QC запрещено.
- Утверждение `ASSAY_REVIEW` означает, что идентификатор белка известен, но **первичная экспериментальная постановка не проверена**. Без дополнительной проверенной связи с описанием опыта и исходной публикацией строки нельзя объявлять окончательно подтверждёнными.
- Полный TSV может включать импортированные записи ChEMBL и дубликаты. **Не суммировать количества ChEMBL+BindingDB как независимые эксперименты** до поиска общих DOI, документов и идентификаторов реакций.

В отчётах используются разные знаменатели, которые нельзя называть одним числом экспериментов: (1) физические строки исходного TSV, (2) связи исходной строки с одной из мишеней панели, (3) отдельные непустые значения Ki/Kd/IC50 и (4) измерения, сохранённые после `max_rows_per_target`. Точные, цензурированные и непарсируемые значения считаются только среди сохранённых измерений и указываются именно с этим знаменателем.

## Организация результата

Все данные записываются в новую папку `reports/TLS_V3_P08_<utc>_<commit>/` с самостоятельным ZIP:

- `p08_target_panel.tsv` — выбранные символы, accession, HGNC и статусы сопоставления;
- `p08_chembl_coverage.tsv`, `p08_bindingdb_coverage.tsv` — полнота просмотра по каждому гену;
- `p08_chembl_observations.tsv`, `p08_bindingdb_observations.tsv` — построчные свидетельства с идентификаторами и статусами;
- `p08_QC.tsv` — нарушения контракта, отсутствующие источники, неоднозначности;
- `p08_summary.json`, `p08_source_manifest.json` — итог, версии, SHA256 до/после, отсутствие сетевых вызовов;
- `P08_REPORT_RU.md` — краткий научный отчёт.

Если научные выгрузки пока не предоставлены: **`technical_status=INPUT_REQUIRED`**, строки измерений пустые, источник **`SOURCE_NOT_PROVIDED_NOT_ASSESSED`**. Это нормальный, безопасный предварительный этап, а не отсутствие лигандов.

## Чего P0.8 не делает

Не скачивает десятки гигабайт данных; не выполняет докинг, молекулярную динамику или поиск структурного сходства PYZ; не формирует новый список противоопухолевых препаратов. Не проводит автоматическую научную приёмку, не объединяет PR. Данные от известных лигандов не приписываются PYZ. Перевод данных в расширенную матрицу — отдельный P1 **после** источникового QC.

# MCL / TLS V3 / P0.7 — проверка надежности экспериментальных источников

Версия: `mcl-tls-v3-p07-source-reliability-v1`. Этап P0.7 **не** является новым исследованием активности PYZ и **не** заменяет полноценную сборку химического пространства P1.

## Исходные данные и неизменяемость

Принимаются **два существующих ZIP**: P0 (локальная инвентаризация) и P0.6 (результаты внешнего пилота). Пайплайн проверяет контракты, пересечение 40 выбранных генов, SHA-256 трех основных таблиц P0 относительно декларации P0.6, количество запросов и SHA каждого из 70 сохранённых ответов. ZIP не распаковывается на диск; опасные пути, дубли, чрезмерные размеры и несогласованные контрольные суммы блокируют анализ. Выход в совершенно отдельную новую папку `MCL_Project/reports/TLS_V3_P07_*`. Библиотеки, API, сайт, 65 PYZ и матрица 65×13 не изменяются.

## Химические данные ChEMBL

Только успешные сохраненные ответы `target.json`, `activity.json`, `assay/{id}.json`. Мишень требует **SINGLE PROTEIN, Homo sapiens, единственный точный UniProt accession**. Для каждой исходной записи хранятся ID измерения, лиганда, исследования, ChEMBL-мишени, тип Ki/Kd/IC50, значение и отношение. Неравенства сохраняются, но не становятся точными результатами. Анализ c `confidence_score=9`, `assay_type=B`, тем же `target_chembl_id` и известной структурой — условие для класса *пример экспериментального анализа проверен по кэшу*. Это **не** означает, что весь белок «готов к докингу» или что измерение применимо к PYZ. Даже высокий ChEMBL confidence-score отражает аннотацию мишени в базе, а не независимую лабораторную репликацию.

### Проблемы охвата

Первые страницы `limit=10` не являются полными источниками, пропущенные ответы не ноль активности. Отдельно формируется очередь для повторных запросов по временному HTTP 5xx, тайм-ауту и превышению размера ответа. Повторный запрос с `only=` использует сокращенные поля без повышения научного уровня. Отсутствие поля `target_components` в повторном ответе — не повод принять соответствие «по имени».

## BindingDB

Исходный REST `getLigandsByUniprots` формирует JSON `getLindsByUniprotsResponse.affinities`. Поле `query` содержит **название белка**, при этом один ответ способен включать несколько названий (семейства/комплексы/связанные мишени). Поэтому считается отдельная группа «запрошенный accession → реальное название из каждой строки» с числами химически пригодных записей, источниками PMID/DOI/monomerid. **Ни одна name-only запись не получает статус верифицированного точного связывания с UniProt без независимых исходных ID мишени и протокола исследования.** HTTP 200 с пустым телом — особый статус `EMPTY_HTTP_200_NOT_NEGATIVE`.

Документы источников: [BindingDB REST](https://www.bindingdb.org/rwd/bind/BindingDBRESTfulAPI.jsp), [ChEMBL API](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services), [ChEMBL assays](https://chembl.gitbook.io/chembl-interface-documentation/frequently-asked-questions/chembl-data-questions).

## Режимы

- **Offline, по умолчанию**: полная разметка сохраненных 40 белков и истории 109 запросов **без сети**, с перечнем запросов для возможного ручного решения.
- **Ограниченный сетевой ремонт**, только явный `-EnableTargetedRetry`: максимум 12 запросов по умолчанию (административный предел 24), только `https://www.ebi.ac.uk` и строго определенные `target.json`, `activity.json`, `assay/{CHEMBL_ID}.json`. Не используются данные других сайтов, не проверяется автоматически BindingDB через новые запросы, нет массового ChEMBL. Ответ ≤900 КБ, суммарно ≤8 МБ, задержка между запросами, без переадресаций, тайм-аут 16 секунд; каждое обращение документируется. Никакого автоматического добора всей базы, автоматического повторного сканирования и обхода лимитов.

Техническая корректность не доказывает научную пригодность всех объектов. **`scientific_acceptance=NOT_APPROVED`, `merge_permitted=false`** до независимого изучения противоречий, оригинальных исследований и достаточности экспериментов. P1 и интеграция PYZ не запускаются автоматически.

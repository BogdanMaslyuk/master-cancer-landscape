## 1. Цель MCL

Master Cancer Landscape (MCL) — исследовательская среда, объединяющая молекулярные мишени, генетические зависимости клеточных моделей, данные о лигандах малых молекул, прогнозы и результаты собственных исследований. Текущая задача — расширить **научно проверяемое пространство мишеней**, а не просто увеличить количество белков или построить очередной общий балл.

В рабочем контексте есть **65 соединений PYZ**, прежняя панель из **13 белков** и **845 пар «соединение—мишень»**. Сохранять их без изменений до отдельной научной приёмки.

Результаты **известных** лигандов ChEMBL/BindingDB не являются измерениями PYZ. Генетическая зависимость CRISPR не доказывает эффективности фармакологического ингибирования. Сходство структур не доказывает связывания и цитотоксичности.

## 3. Научное положение на момент передачи

- P0 на реальных локальных данных: 17/17 источников; 20 050 строк объединённого каталога, из них `UNNAMED: 0` — подозрительный служебный заголовок. **20 049 валидных генных кандидатов** после его исключения. **1 947** однозначных соответствий с reviewed-белками в *старом локальном* реестре, не граница человеческого протеома. Для старой панели локальные прямые данные лигандов есть только по 13 белкам.
- P0.6: 40 мишеней и 109 внешних запросов; 18 986 генов из локального каталога точно сопоставлены с reviewed UniProt+HGNC в соответствующем снимке. Это подтверждение идентичности, **не наличия лигандов**.
- В пилоте P0.6 наблюдались ошибки HTTP 500, ограничения размера ответа и неоднозначные ответы BindingDB. Не интерпретировать ошибки как отсутствие экспериментальных записей.
- P0.7 повторил 12 запросов, **0 успешных** (8 тайм-аутов и 4 HTTP 500). Оставленные в кэше материалы позволяют обсуждать **38 предварительных точных численных измерений ChEMBL** для PRKDC, BCL2L1, IGF1R, ERBB3, FNTB, DDC, из которых два измерения FNTB прошли дополнительную проверку метаданных assay. **21 055** химически пригодных строк BindingDB остались *name-only* и не подтверждены на уровне точного UniProt по каждой исходной записи.
- Решение: не повторять прежний широкий REST-поиск, а перейти на **версионированные локальные выгрузки**.
- P0.8 реализован и протестирован на искусственных SQLite/TSV; **реальный анализ полных ChEMBL SQLite и BindingDB TSV/ZIP ещё не завершён**, поскольку наличие и пути этих выгрузок на компьютере исследователя не подтверждены. Без них ожидаемый статус `INPUT_REQUIRED`.

Не превращать тесты и технический успех запуска в утверждение о научной достоверности. Контрольные результаты — только ориентиры для проверки отчётов.

## 6. Правила и критерии для P0.8

- Источники только на чтение: ChEMBL SQLite через `mode=ro`, BindingDB TSV/ZIP потоком, научные снимки и ZIP P0–P0.7 не изменять.
- Первая панель: PRKDC (`P78527`), BCL2L1 (`Q07817`), IGF1R (`P08069`), ERBB3 (`P21860`), FNTB (`P49356`), DDC (`P20711`). Только после её научной ревизии — 40 и более.
- ChEMBL: только человеческая `SINGLE PROTEIN` с однозначным accession; исходные B-assay, `confidence_score=9`; Ki/Kd/IC50 и единицы; сохранять отношения `=`/`<`/`>`, QC-флаги, документы, ID assay/activity/molecule. Проверка метаданных не равна самостоятельной ревизии публикации.
- BindingDB: использовать все повторяющиеся колонки `UniProt (SwissProt) Primary ID of Target Chain` и число цепей, не `Target Name`; сохранять PMID/DOI, MonomerID, Reactant_set_id и признаки неоднозначности. Не складывать данные двух баз без дедупликации.
- Отсутствующий источник — `INPUT_REQUIRED` / `NOT_ASSESSED`, никогда «лигандов нет».
- Отчёты в новой изолированной папке, с SHA, QC и раздельными количествами проверенных / условно пригодных / отклонённых / неоценённых записей.
- **Запрет** на пересборку 65×13, докинг, P1, изменение API/сайта или автоматическое слияние PR без отдельного согласия.

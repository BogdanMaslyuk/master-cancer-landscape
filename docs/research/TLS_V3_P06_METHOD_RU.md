# MCL — TLS V3 / P0.6. Контролируемая оценка расширяемости пространства мишеней

**Статус:** реализация для научного аудита; `scientific_acceptance=NOT_APPROVED`, `merge_permitted=false`. Матрица 65 × 13 и генетические источники не изменяются.

## Задача

Продолжить P0, не смешивая (1) правильное сопоставление человеческого гена и белка, (2) наличие прямых экспериментальных измерений **известных** лигандов и (3) вероятность связывания PYZ, которая **не рассчитывается**.

Пилот включает два уровня: (а) один проверяемый снимок reviewed human UniProtKB, сопоставляемый по **точному основному символу** с генным каталогом MCL; HGNC ID записывается отдельно, совпадение с локальным UniProt проверяется на конфликты; (б) ограниченный, явно разрешённый поиск по экспериментальным базам для стратифицированной выборки **до 50** генов. Отсутствующие, неоднозначные или конфликтующие соответствия не направляются в запросы по лигандам.

## Границы и организация выборки

Выборка по умолчанию 40 (алгоритмическая, по SHA256(seed + gene_symbol), независимая от порядка строк): 13 прежних контрольных мишеней; до 12 генов с nonpriority Candidate v2 и однозначным локальным соответствием; до 7 других однозначно сопоставленных; до 8 с CRISPR, но без локального белкового соответствия. Недостающее количество добирается независимо и воспроизводимо из всех остальных валидных кандидатов. Подозрительные индексы `UNNAMED: N` не выбираются.

**Такая выборка не является статистически репрезентативной выборкой человеческого протеома.** Ни доля белков с лигандами, ни вероятность активности PYZ за пределами выборки не экстраполируются.

## Источники

- **UniProtKB:** `https://rest.uniprot.org/uniprotkb/stream`; запрос `organism_id:9606 AND reviewed:true`; поля `accession,gene_primary,xref_hgnc,protein_name`; проверяются колонки, уникальность accession, размер полноты; сохраняются сырой ответ, SHA256 и ответные заголовки версии (если доступны). Число reviewed записей ≠ число уникальных генов ≠ число лекарственных мишеней. Отсутствие HGNC и конфликт со старым реестром — `REVIEW_REQUIRED`.
- **ChEMBL:** `https://www.ebi.ac.uk/chembl/api/data/target.json`, затем `activity.json` с **одной проверенной SINGLE PROTEIN мишенью человека**, отдельно Ki/Kd/IC50 в nM, с `assay_type=B`; первые 10 строк на каждый тип и максимум два уникальных assay ID дополнительно сверяются в `assay/{id}.json`. Для статуса подтверждённого *примера* прямого измерения необходимы точная мишень, тип анализа `B` и `confidence_score=9`. `page_meta.total_count` — число кандидатов по запросу, а не число научно проверенных прямых измерений. Статус по отдельным примерам нельзя экстраполировать на весь ChEMBL.
- **BindingDB:** `https://www.bindingdb.org/rest/getLigandsByUniprots` с одним UniProt accession, `cutoff=10000` nM и JSON-ответом. Проверяются видимые типы, неравенства, непустая структура и явно упомянутый точный UniProt. Это **кандидатные записи**, не верифицированная прямая активность: формат/полнота источника могут требовать дальнейшей проверки первичного анализа. При пустом или неожиданном JSON писать `NO_PARSEABLE_RECORDS_OR_EMPTY` / `ERROR`, **не** утверждать отсутствие лигандов.

Документация: [официальное описание UniProt API](https://github.com/ebi-uniprot/uniprot-manual/blob/main/help/api_queries.md), [ChEMBL Web Services](https://chembl.gitbook.io/chembl-interface-documentation/web-services/chembl-data-web-services), [BindingDB RESTful API](https://www.bindingdb.org/rwd/bind/BindingDBRESTfulAPI.jsp).

## Воспроизводимость и ограничения сети

По умолчанию `--offline` и **0 сетевых вызовов**. Сеть включается только аргументом `--enable-external-pilot`, который невозможно совместить с `--offline`. Разрешены только три фиксированных HTTPS-хоста; переадресации запрещены; не допускаются пользовательские произвольные URL; по умолчанию максимум 320 запросов, общий бюджет 50 MB, один UniProt ответ не более 5 MB и один BindingDB ответ не более 2 MB, задержка между запросами, тайм-аут 25 секунд. Кэш `external_response_cache` находится исключительно внутри новой папки отчёта; сохраняется SHA каждого ответа. Не используется автоматика восстановления через полный обход внешних баз.

Весь входной отчёт P0 проверяется по SHA256 до и после; P0.6 записывает только новую самостоятельную папку `MCL_Project/reports/TLS_V3_P06_...`. Никаких исходных научных Parquet, TSV, NPY, конфигураций PYZ, интерфейсов и API не менять. Старые 13 мишеней остаются неизменным контролем. Не вводить «интегральные баллы эффективности».

## Требования к приёмке

- Повторить исправленный P0 и проверить его архив (исправление технического артефакта `UNNAMED: 0`, строгий T4).
- Выполнить локальные тесты, затем воспроизводимый автономный прогон P0.6, затем при явном согласии оператора — ограниченный внешний пилот.
- Проверить реальный отчёт, ошибки HTTP, конфликты идентификаторов и первичные ID пробных биохимических экспериментов.
- **До ручной научной приёмки число мишеней для P1 не объявлять подтверждённым; не объединять PR.**

# MCL: структурное сравнение собственных соединений v1

## Задача

Этот слой отвечает на узкий вопрос:

> На какие **известные соединения, связанные с уже перспективными мишенями MCL**, структурно похожи наши собственные синтезируемые молекулы?

Это не target prediction и не доказательство механизма действия. Биологический фильтр применяется **до** химического сравнения: в поиск попадают только мишени, для которых Candidate v2 уже содержит хотя бы одну гипотезу со статусом `priority_for_in_vitro`.

## Почему поток устроен именно так

Полный поиск потенциальных мишеней для новой молекулы может вернуть много белков, которые не имеют выраженной терапевтической уязвимости в интересующих нас опухолевых моделях. Полный docking по всем возможным белкам также пока нецелесообразен.

Поэтому v1 использует обратный маршрут:

`перспективная мишень MCL -> известные соединения этой мишени -> структура известного соединения -> Tanimoto с нашей молекулой`

После этого результат можно вернуть в уже существующий MCL-контекст: опухоли, клеточные модели, CRISPR-зависимость, PRISM и лабораторную доступность.

## Единственный рабочий реестр собственных соединений

Источник конфигурации: `config/own_compounds.tsv`.

С 06.10.2026 рабочим реестром являются **только 65 соединений `PYZ-001 ... PYZ-065`**, сопоставленных визуальным структурным формулам из приложения `SYL-RPT-2026-023 · Приложение A`.

Старый временный набор `OWN-CMP-001 ... OWN-CMP-020 / CMP-001 ... CMP-020` больше не является источником собственных соединений для MCL и не должен использоваться в новых расчётах.

Номер `PYZ-###` является главным идентификатором молекулы в MCL. Один и тот же номер используется как `own_compound_id`, `source_molecule_id` и `preferred_name`.

Перед каждым полным расчётом `scripts/build-own-compound-similarity.ps1` запускает `scripts/validate_pyz65_registry.py`, который требует:

- ровно 65 строк;
- непрерывный порядок `PYZ-001 ... PYZ-065`;
- непустой SMILES для каждой структуры;
- успешный RDKit parsing для 65/65;
- отсутствие структурных дубликатов после RDKit canonicalization.

Если это условие нарушено, расчёт должен остановиться, а не продолжить работу со старым или неполным реестром.

## Универсум сравнения

1. Из `candidate_hypotheses_v2.parquet` выбираются строки `priority_status = priority_for_in_vitro`.
2. Формируется множество генов-мишеней этих гипотез.
3. Из `target_compound_catalog.parquet` берутся **все известные соединения**, связанные с этими мишенями.
4. Сравнение не ограничивается только конкретными приоритетными гипотезами. У перспективной мишени может существовать несколько известных лигандов, и структурно ближайшим к PYZ-молекуле может оказаться другой лиганд той же мишени.
5. Если в исходном фармакологическом каталоге нет структуры известного соединения, используется отдельный трассируемый слой обогащения структур. Исходный каталог при этом не перезаписывается.
6. Соединения без валидной структуры не участвуют в Tanimoto и учитываются в QC.

## Стандартизация структуры

Одинаково для собственной и известной молекулы:

`MolFromSmiles -> rdMolStandardize.Cleanup -> FragmentParent -> canonical isomeric SMILES -> sanitize/ring initialization`

В manifest сохраняются параметры метода. Слой не пытается автоматически выбрать биологически активный таутомер, протонированное состояние или конформацию.

## Fingerprint и сходство

Основной воспроизводимый метод v1:

- RDKit Morgan bit fingerprint;
- radius = 2;
- 2048 bits;
- chirality flag в fingerprint = false;
- метрика = Tanimoto.

Пороговые категории служат **только описанием 2D-сходства**:

- `>= 0.70` — high_2d_similarity;
- `0.50–0.70` — moderate_2d_similarity;
- `0.35–0.50` — low_notable_2d_similarity;
- `< 0.35` — weak_2d_similarity.

Эти границы не являются вероятностью общей мишени и не имеют клинического смысла.

## Что записывается

`data/runtime/own_compounds/own_compounds.parquet`
: валидированный реестр PYZ после RDKit-обработки.

`data/runtime/own_compounds/similarity_hits.parquet`
: все пары `PYZ × известное соединение × перспективная мишень`, для которых известна структура.

`data/runtime/own_compounds/top_similarity_hits.parquet`
: лучшие структурные соседи глобально и внутри каждой мишени.

`data/runtime/own_compounds/target_similarity_summary.parquet`
: одна строка на `PYZ × мишень`, лучший известный структурный сосед и контекст Candidate v2.

`data/runtime/own_compounds/target_similarity_summary.tsv`
: человекочитаемая версия предыдущего файла.

`outputs/qc/own_compound_similarity_qc.tsv`
: структуры, которые не удалось корректно использовать.

`data/runtime/own_compounds/own_compound_similarity_manifest.json`
: параметры fingerprint, покрытие структурами и научный контракт слоя.

## Как трактовать результат

Корректная формулировка:

> `PYZ-0XX` имеет определённое 2D-сходство с известным соединением Y, связанным с мишенью Z. Поскольку Z имеет приоритетный MCL-контекст, это создаёт проверяемую гипотезу для дальнейшего изучения.

Некорректная формулировка:

> `PYZ-0XX` ингибирует Z, потому что похож на Y.

Высокий Tanimoto сам по себе не устанавливает:

- общую мишень;
- одинаковое положение в кармане;
- одинаковый тип действия;
- сходную аффинность или селективность;
- одинаковую клеточную активность;
- терапевтический потенциал.

## Текущий следующий шаг

После смены реестра необходимо заново запустить полный structural-similarity build. Результаты, полученные ранее для временных `OWN-CMP-*`, считаются устаревшими и не должны использоваться для интерпретации PYZ-ряда.

Далее для наиболее интересных структурных соседей маршрут остаётся:

`PYZ -> структурный сосед -> известная мишень -> Candidate v2 -> подходящие клеточные модели -> лабораторная панель`.

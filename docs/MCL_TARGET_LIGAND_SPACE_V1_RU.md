# MCL Target Ligand Space v1

## Задача

Этот слой расширяет химическое пространство вокруг **текущих мишеней Candidate v2 со статусом `priority_for_in_vitro`**.

Предыдущий строгий слой `oncology_reference_compounds` отвечает на вопрос:

> На какие хорошо интерпретируемые противоопухолевые препараты похожи PYZ-соединения?

Target Ligand Space v1 отвечает на другой вопрос:

> Есть ли среди **экспериментально измеренных малых лигандов конкретной мишени** химически близкие структуры к PYZ-001...PYZ-065?

Это принципиально более широкая библиотека. Она включает не только лекарства и клинические кандидаты, но и исследовательские соединения с прямыми экспериментальными измерениями взаимодействия с белком.

## Источники

### ChEMBL

Официальный REST API:

`https://www.ebi.ac.uk/chembl/api/data`

Для каждой мишени сначала разрешается точная запись:

- UniProt accession из `data/processed/target_registry/protein_targets.parquet`;
- организм `Homo sapiens`;
- `target_type = SINGLE PROTEIN`;
- UniProt accession должен входить в `target_components`.

После этого загружаются активности этой ChEMBL-мишени.

### BindingDB

Официальный REST endpoint:

`https://www.bindingdb.org/rest/getLigandsByUniprots`

Запрос выполняется отдельно для каждого UniProt accession. Такой маршрут уменьшает риск смешивания мишеней и позволяет сохранить однозначную связь с MCL target gene.

## Какие измерения включаются

Рабочий порог v1 по умолчанию:

`<= 10 000 нМ`

Порог нужен не как граница терапевтической эффективности, а как технический фильтр, чтобы химическое пространство не размывалось очень слабыми аннотациями.

Разрешённые типы измерений:

- `Ki`;
- `Kd`;
- `IC50`.

### ChEMBL

В основной слой допускаются только записи, для которых:

- мишень разрешена как точный человеческий `SINGLE PROTEIN`;
- `standard_relation = =`;
- единицы — нМ;
- значение положительное и не выше заданного порога;
- структура соединения доступна;
- отсутствует `data_validity_comment`;
- запись не помечена как потенциальный дубль;
- исключены клеточные, организменные и тканевые форматы;
- для прямой интерпретации требуется `single protein format` либо binding-assay контекст.

Это намеренно консервативный фильтр. Он может потерять часть пригодных функциональных измерений, но уменьшает риск принять клеточный фенотип за прямое взаимодействие с белком.

### BindingDB

Используются `Ki`, `Kd`, `IC50` в пределах порога. Нулевые значения считаются неинформативными и исключаются. Нижние границы вида `>X` не используются как доказательство достаточной активности. Значения `<X` сохраняются как верхняя граница истинного значения.

Если BindingDB явно указывает в записи другой UniProt accession, такая запись исключается из текущей мишени.

## Стандартизация и объединение

Все структуры проходят одинаковый путь RDKit:

`MolFromSmiles -> Cleanup -> FragmentParent -> canonical isomeric SMILES -> InChIKey`

Дедупликация выполняется внутри каждой мишени по:

`target_gene + standardized InChIKey`

Поэтому одна химическая структура может корректно присутствовать у нескольких белков, если для неё действительно существуют измерения по нескольким мишеням.

Для каждого уникального `мишень × лиганд` сохраняются:

- источники (`ChEMBL`, `BindingDB` или оба);
- исходные идентификаторы;
- типы endpoint;
- число экспериментальных измерений;
- минимальное зарегистрированное численное значение и его тип.

Важно: поле `lowest_reported_value_nm_across_endpoints` служит только навигации. **Ki, Kd и IC50 не считаются взаимозаменяемыми величинами.** Исходный тип endpoint всегда сохраняется.

## Сходство с PYZ

Используется тот же химический метод, что и в предыдущих слоях:

- Morgan bit fingerprint;
- radius = 2;
- 2048 bits;
- chirality flag = false;
- Tanimoto similarity.

Категории остаются описательными:

- `>= 0.70` — `high_2d_similarity`;
- `0.50–0.70` — `moderate_2d_similarity`;
- `0.35–0.50` — `low_notable_2d_similarity`;
- `< 0.35` — `weak_2d_similarity`.

Для каждой пары `PYZ × мишень` рассчитывается сходство со **всеми** уникальными экспериментальными лигандами этой мишени. В сводке сохраняются:

- число сравненных лигандов;
- число соседей с Tanimoto >= 0.35 / 0.50 / 0.70;
- лучший структурный сосед;
- его источники и экспериментальные endpoint;
- минимальное зарегистрированное значение с обязательным указанием типа endpoint.

Полный матричный набор всех миллионов возможных пар намеренно не записывается. Сохраняются точные пороговые количества и лучшие соседи для каждой пары `PYZ × мишень`, чтобы не создавать тяжёлый бессмысленный runtime-файл.

## Научная интерпретация

Корректно:

> PYZ-X имеет Tanimoto 0.62 с экспериментальным лигандом белка Y. Для известного лиганда зарегистрировано прямое измерение взаимодействия с Y. Это повышает приоритет пары PYZ-X–Y для дальнейшей проверки.

Некорректно:

> PYZ-X связывает Y с той же аффинностью, потому что Tanimoto высокий.

Структурное сходство **не доказывает**:

- связывание PYZ с мишенью;
- общий механизм действия;
- одинаковое положение в кармане;
- одинаковую Ki/Kd/IC50;
- селективность;
- противоопухолевую активность.

Даже высокий Tanimoto здесь остаётся генератором экспериментально проверяемой гипотезы.

## Связь с другими слоями MCL

Предлагаемая логика интерпретации:

```text
Candidate v2
мишень важна для жизнеспособности опухолевой модели
        ↓
Strict oncology references
существует ли валидированный противоопухолевый фармакологический маршрут
        ↓
Target Ligand Space
есть ли близкие экспериментально измеренные химические соседи PYZ
        ↓
структурный / механистический анализ
докинг, фармакофор, target engagement
        ↓
лабораторная проверка
релевантная опухолевая линия + отрицательный контроль + нетуморный контроль
```

Target Ligand Space **не заменяет** строгий каталог противоопухолевых препаратов. Эти два слоя отвечают на разные вопросы и должны сохраняться параллельно.

## Запуск

```powershell
.\scripts\build-target-ligand-space.ps1
```

По умолчанию используется порог 10 000 нМ.

Пример более строгого exploratory cutoff:

```powershell
.\scripts\build-target-ligand-space.ps1 -CutoffNm 1000
```

Принудительное обновление внешних API-кэшей:

```powershell
.\scripts\build-target-ligand-space.ps1 -ForceRefresh
```

Кэш внешних ответов сохраняется в `data/external/target_ligand_space/v1/` и не коммитится в Git.

## Основные выходы

`data/runtime/target_ligand_space/target_map.tsv`
: текущие приоритетные MCL-мишени и UniProt mapping.

`data/runtime/target_ligand_space/ligand_measurements.parquet`
: прошедшие фильтр экспериментальные измерения.

`data/runtime/target_ligand_space/ligand_catalog.parquet`
: дедуплицированный каталог `мишень × структура`.

`data/runtime/target_ligand_space/target_summary.tsv`
: покрытие каждой мишени ChEMBL и BindingDB.

`data/runtime/own_compounds/target_ligand_space_similarity_summary.tsv`
: главный компактный результат `PYZ × мишень`.

`data/runtime/own_compounds/target_ligand_space_similarity_top_hits.tsv`
: лучшие экспериментальные структурные соседи.

`outputs/qc/target_ligand_space_qc.tsv`
: исключённые/неразрешённые записи и причины.

`outputs/qc/target_ligand_space_similarity_qc.tsv`
: структуры, которые не удалось использовать в fingerprint-анализе.

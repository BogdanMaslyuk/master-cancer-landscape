# MCL: слой доклинических in vivo данных (Preclinical Database) v1

## Зачем он нужен

Этот слой не определяет мишень препарата и не доказывает эффективность лечения. Его задача уже:

> показать, какие известные соединения вокруг приоритетных мишеней MCL действительно встречаются в доклинических **in vivo** исследованиях и при каких заболеваниях/животных моделях они изучались.

Он дополняет, а не заменяет:

- ChEMBL / BindingDB — прямую фармакологию `соединение ↔ мишень`;
- PRISM — клеточный фармакологический фенотип;
- DepMap CRISPR — генетическую зависимость опухолевой модели;
- клинические источники — одобрение и клинические исследования.

## Источник

Preclinical Database (PCDB), AIFS / University of California, Davis.

Зафиксированная базовая версия для MCL v1: `PCDB v1.0` (релиз 2026-07-23).

Слой использует публичную bulk-выгрузку, а не требует персонального API-ключа. Исходные файлы сохраняются только локально в `data/external/preclinical_db/` и не коммитятся в Git.

## Загрузка

```powershell
.\scripts\build-preclinical-evidence.ps1
```

Скрипт:

1. открывает официальную страницу загрузок PCDB;
2. находит ссылку на `preclinical-db-v1.0.zip`;
3. скачивает архив;
4. вычисляет локальный SHA256;
5. безопасно распаковывает архив;
6. находит `pcdb_complete.tsv`;
7. строит слой MCL.

Если автоматическое обнаружение официальной ссылки перестало работать:

```powershell
.\scripts\build-preclinical-evidence.ps1 -DownloadUrl "<официальная ссылка на ZIP>"
```

Для публикационной заморозки необходимо отдельно сверить записанный SHA256 с полной контрольной суммой, опубликованной PCDB.

## Какие соединения рассматриваются

Сначала MCL берёт только гены-мишени, имеющие хотя бы одну гипотезу Candidate v2 со статусом:

`priority_for_in_vitro`

Затем из `target_compound_catalog.parquet` берутся известные соединения, связанные с этими мишенями.

PCDB **не используется для назначения мишени**. Он только добавляет сведения об in vivo исследовании уже известного соединения.

## Сопоставление соединений

В v1 автоматическое сопоставление максимально консервативное:

`MCL preferred_name == PCDB drug name` после технической нормализации регистра, пробелов и пунктуации.

Fuzzy matching не используется.

Это намеренно снижает полноту, но уменьшает риск приписать публикацию не тому препарату.

В следующих версиях можно добавить независимую проверку через PubChem CID / DrugBank / ChEMBL после изучения реальной схемы entity-каталогов PCDB v1.0.

## Связь с опухолью

Слой разделяет два уровня.

### 1. `disease_looks_oncologic`

Это только описательный флаг по словам `cancer`, `carcinoma`, `leukemia`, `lymphoma`, `melanoma`, `sarcoma`, `glioma`, `neoplasm`, `tumor` и др.

Он означает лишь, что название заболевания похоже на онкологическое. Это **не** доказывает совпадение с опухолевым контекстом MCL.

### 2. `exact_priority_cancer_match`

Этот флаг ставится только когда нормализованное название заболевания PCDB точно совпадает с названием опухолевого контекста, для которого соответствующая мишень имеет `priority_for_in_vitro` в MCL.

Никакого автоматического расширения `NSCLC -> lung cancer`, `glioblastoma -> diffuse glioma` и т. п. в v1 нет.

Для более полного сопоставления нужен отдельный курируемый слой онтологии/синонимов заболевания.

## Выходные файлы

`data/runtime/preclinical/preclinical_compound_records.parquet`
: строковые связи `мишень MCL → соединение → запись PCDB → заболевание → животная модель → PMCID`.

`data/runtime/preclinical/preclinical_compound_records.tsv`
: человекочитаемая версия.

`data/runtime/preclinical/preclinical_compound_summary.tsv`
: сводка по известному соединению — сколько записей/публикаций PCDB, сколько онкологических и сколько точно совпадает с приоритетным опухолевым контекстом MCL.

`data/runtime/preclinical/preclinical_target_summary.tsv`
: сводка по каждой приоритетной мишени.

`data/runtime/preclinical/preclinical_evidence_manifest.json`
: контракт, версия источника и правила интерпретации.

`outputs/qc/preclinical_unmatched_pcdb_drug_names.tsv`
: имена препаратов PCDB, которые не были автоматически сопоставлены с известными соединениями MCL.

## Научная интерпретация

Допустимая формулировка:

> Соединение X, связанное в MCL с мишенью Y, представлено в PCDB в in vivo исследованиях заболевания Z; доступны исходные PMCID.

Недопустимая формулировка:

> PCDB доказал, что ингибирование Y соединением X лечит опухоль Z.

PCDB v1.0 не содержит в этом слое:

- величины противоопухолевого эффекта;
- effect size;
- доказательства target engagement;
- доказательства, что эффект опосредован именно рассматриваемой мишенью;
- оценки риска систематической ошибки;
- автоматического вывода об эффективности.

## Как этот слой войдёт в Oncology Reference Compounds

Будущий строгий эталонный набор должен формироваться пересечением независимых доказательств:

`прямая фармакология мишени`  
`+ противоопухолевая клеточная активность`  
`+ MCL CRISPR-зависимость релевантной опухоли`  
`+ PCDB in vivo evidence`  
`+ клинический/регуляторный статус, если он есть`.

Только после этого такие соединения следует использовать как основной химический референс для Tanimoto с PYZ-001…PYZ-065.
